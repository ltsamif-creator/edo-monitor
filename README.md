# EDO Monitor — микросервис мониторинга документов в Контур.Диадок

## 1. Цель
Отдельный микросервис для специалиста оператора ЭДО, который показывает три категории проблемных документов:
1. **Не подписаны контрагентом** — отправлены в Диадок, но ответная подпись не получена.
2. **Не отправлены из ЕРП** — документы, которые должны были быть отправлены, но не попали в Диадок.
3. **Ошибки отправки / ГИС МТ** — документы, которые пытались отправиться автоматически, но выпали в ошибку, либо не прошли проверку в ГИС МТ.

## 2. Роли
- **Оператор ЭДО** — просматривает списки проблемных документов и предпринимает действия (связь с клиентом, исправление в ЕРП).
- **Администратор** — настраивает подключение к Диадоку, путь к папке выгрузки, расписание опроса.

## 3. Сценарии использования
1. Оператор видит документ, который **не прошёл ГИС МТ**, и уведомляет ответственного.
2. Оператор видит документ, **давно не подписанный контрагентом**, и связывается с клиентом по доступным каналам.
3. Оператор видит документ, который **не отправился из ЕРП**, и предпринимает действия в 1С для его отправки.

## 4. Критерии приёмки
- Сервис отображает все три категории проблемных документов.
- Оператор понимает, что нужно делать с каждым документом (категория + краткое описание проблемы).
- Данные обновляются не реже, чем раз в 10 минут.
- Сервис разворачивается одной командой `docker-compose up`.

## 5. Технический стек
- **Язык:** Python 3.11
- **Фреймворк:** FastAPI
- **БД:** SQLite (файл `edo_monitor.db`)
- **Планировщик:** APScheduler
- **HTTP-клиент:** httpx
- **Развёртывание:** Docker + Docker Compose

## 7. Источники данных

### 7.1. Папка выгрузки из 1С (`data/incoming/`)
1С ERP выгружает в эту папку JSON-файлы с документами, предназначенными к отправке.  
Формат файла — один документ на файл, имя файла — `{GUID_документа}.json`.  
Пример содержимого:

```json
{
  "document_id": "a1b2c3d4-...",
  "document_number": "УПД-000123",
  "document_date": "2025-01-15",
  "counteragent_inn": "7701234567",
  "counteragent_name": "ООО Ромашка",
  "document_type": "УПД",
  "status_1c": "К отправке",
  "exported_at": "2025-01-15T10:00:00Z"
}

7.2. Контур.Диадок API
Базовый URL: https://diadoc-api.kontur.ru

Авторизация: токен в заголовке Authorization: Bearer {token} (или сертификат).

Основные методы:

GetDocflowEvents — получение событий по документам.

GetMessage (V6) — детальная информация о сообщении и подписях.

CanPostMessage — проверка возможности отправки.

Документация: https://developer.kontur.ru/docs/diadoc-api/index.html

9. Логика работы
9.1. Синхронизация с 1С (парсер папки)
Планировщик каждые 5 минут обходит data/incoming/.

Для каждого нового .json-файла:

Парсит документ.

Сохраняет в таблицу documents (если ещё нет).

Помечает файл как обработанный (перемещает в data/processed/).

9.2. Синхронизация с Диадоком
Планировщик каждые 10 минут вызывает GetDocflowEvents с afterIndexKey (последняя обработанная позиция).

Новые события сохраняются в docflow_events.

Для документов, у которых изменился статус, обновляется documents.diadoc_status.

9.3. Детектор проблем
После каждой синхронизации запускается модуль problem_detector, который:

Не подписаны контрагентом
Документы, у которых diadoc_status = OutboundWaitingForRecipientSignature и с момента отправки прошло более 3 дней.

Не отправлены из ЕРП
Документы из documents, у которых status_1c = К отправке, но diadoc_message_id пуст, и с exported_at прошло более 1 часа.

Ошибки отправки / ГИС МТ

События с типами OutboundInvalidSenderSignatures, OutboundDeliveryError, а также события, связанные с ГИС МТ (если API возвращает соответствующие статусы).

Документы, по которым CanPostMessage вернул ошибку (если удаётся связать).

Найденные проблемы записываются в таблицу problems с типом и описанием.

9.4. REST API для оператора
GET /api/problems — список всех проблемных документов с фильтрацией по типу.

GET /api/documents/{document_id} — детали документа и история событий.

POST /api/problems/{id}/resolve — пометить проблему как решённую (оператор вручную).

Визуализация не требуется — оператор работает через HTTP-клиент (Postman, curl) или простой Swagger UI, который FastAPI предоставляет автоматически (/docs).
